## 0. 使用方式

1. 主理人逐项问，**一次问完**（不要挤牙膏式追问，用户时间更贵）。
2. 用户答"你看着办"的项 → 主理人**给出建议值并明确标注"建议值，未确认"**，写入状态文件 `pending_confirm`，
   在**第一轮轮报**里请用户追认；**不得**在未追认的情况下进入制作阶段。
3. 第 1–5 项（A 类）**缺任一即不得开工**；第 6–10 项（B 类）可边跑边补，但**必须在制作前置门前补齐**。

### 10. 用户指定参考资料（PDF / URL / 本地文件）— B 类

**为什么单列一项**：需求原文要求工作流能消费「**我指定的 PDF、URL**」作为权威来源。
此前接单九项**无此通道**——用户即使在对话里丢来一份教材 PDF 或一个官方页面，
也只会变成聊天记录里的一句话，既不落盘、也不进证据链，成员无法复查它是否被真正用过。

**归 B 类的理由**：**不指定不影响开工**（无指定源时走域档案的常规检索通道即可），
但**指定了就必须被消费**——所以它不进 A 类「缺一即停」，而是走
「**制作前置门前必须补齐**」：进入制作阶段前，要么已消费并落盘，要么显式标 `[待核实]`。

**采集方式**：主理人在接单追问时**顺手问一句**（不要单独开一轮）——
「这次有没有您指定的教材 PDF、官方页面或本地文件？有的话把路径/链接给我，我按它来核。」

**落盘字段**（写进 `loopB_state.json` 的 `intake.user_sources`，数组，可为空）：

```json
"user_sources": [
  {
    "type": "pdf",
    "path": "/Users/xxx/教材/第3章XX防治.pdf",
    "url": null,
    "purpose": "本课案例来源与数值口径的唯一依据",
    "access": "confirmed",
    "note": "用户提供；须按原书页码标注引用"
  },
  {
    "type": "url",
    "path": null,
    "url": "https://example.gov.cn/notice/123",
    "purpose": "现行监管口径（须核验生效日期）",
    "access": "pending",
    "note": "待核实：页面返回 403，尚未读到原文"
  }
]
```

**字段语义**：

| 字段 | 取值 | 说明 |
|---|---|---|
| `type` | `pdf` / `url` / `local_file` | 决定**定位方式**（本地路径用 Read / URL 用 WebFetch / PDF 提取用 markitdown 或 pdftotext） |
| `path` | 本地绝对路径或 `null` | 只存绝对路径；相对路径一律先解析为绝对路径再落盘 |
| `url` | `http(s)` 链接或 `null` | 与 `path` 二选一，**不同时非空** |
| `purpose` | 自由文本 | **必填**：这份源用来定什么（口径依据 / 案例出处 / 配图来源 / 待核事项） |
| `access` | `confirmed` / `pending` / `unavailable` | `pending`/`unavailable` ⇒ 相关结论标 `[待核实]`，**不得进入正式内容** |
| `note` | 自由文本 | 补充说明（版权限制、需脱敏、用户提供但未授权转载等） |

**硬规则**（与 `config/domain-profiles.yaml#domains[].user_supplied_sources` 一致）：

1. **用户指定源 > 域档案通用检索**——同一主题下，用户指定的源**优先**；
   但**不得因此跳过机构轴核验**（指定源若与机构权威源冲突，见下方第 2 条）。
2. **冲突时按机构轴优先 + 显式提示**：用户指定源与机构权威源结论冲突时，
   按域档案 `evidence_hierarchy` 的**机构轴优先**，并按
   `references/adjudication-rules.md` 的**证据冲突并列原则**显式提示冲突、并列呈现双方，
   **不得**由成员自行抹平或隐去一方。
3. **取不到就标 `[待核实]`**：路径不存在 / URL 不可达 / 权限不足 / 内容为空
   ⇒ 该源涉及的结论标 `[待核实]`，**不得进入正式内容**，并在 `issues` 上抛。
4. **引用必可追溯**：从指定源引出的每条结论须附**可复查的定位**（PDF 页码/章节号、
   URL + 访问日期），不得只写「据用户提供资料」。
5. **版权与许可按源判定**（不豁免）：用户提供的材料**不因"是用户给的"而免版权约束**——
   公开可读 ≠ 可转载；涉及整页复制/配图再发布的，须先确认授权，否则只引用不复制。

## 落盘要求

开工前把这十项写进 `loopB_state.json` 的 `intake` 字段：

```json
{
  "intake": {
    "audience": {"value": "高职大二", "status": "confirmed|suggested"},
    "hours": {"value": 2, "status": "confirmed|suggested"},
    "template": {"value": "沿用原模板", "status": "confirmed|suggested"},
    "scope": {"value": "全部 65 页", "status": "confirmed|suggested"},
    "acceptance": {"value": "...", "status": "confirmed|suggested"},
    "purpose": {"value": "日常授课", "status": "suggested"},
    "delivery": {"value": "成品 PPTX", "status": "suggested"},
    "asset_constraints": {"value": "禁用 AI 生成图", "status": "confirmed"},
    "prohibitions": {"value": "封面与致谢页不动", "status": "suggested"},
    "user_sources": [
      {"type": "pdf", "path": "/abs/path/教材.pdf", "url": null,
       "purpose": "案例与数值口径依据", "access": "confirmed", "note": "按原书页码标注"},
      {"type": "url", "path": null, "url": "https://example.gov.cn/x",
       "purpose": "现行监管口径", "access": "pending", "note": "待核实：未读到原文"}
    ]
  }
}
```

> `user_sources` 为**数组**，无指定源时写 `[]`（不是 `null`、不省略）——
> 省略会让"用户没指定"与"主理人漏问"无法区分。
> 机器侧：`harness.py loop intake` 只校验 A 类五项；`user_sources` 由成员侧按
> `config/domain-profiles.yaml#domains[].user_supplied_sources` 的策略消费。

**制作前置门（round-review-sop#8）追加一条硬检查**：`intake` 中 A 类 5 项 `status` 必须全为 `confirmed`——
存在 `suggested` 即不得进入制作阶段，须先在轮报中请用户追认。
**另加一条（B 类第 10 项专项）**：`intake.user_sources` 中每条 `access != "pending"` 的源，
其结论要么已在证据包中带定位引用，要么已标 `[待核实]` 并从正式内容剔除——**二者皆无 = 未消费指定源 = 不得进制作**。
