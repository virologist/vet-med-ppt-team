## 四、本批实测揪出的真缺陷（均由成员或独立验证发现，非自述）

1. **【P0】标量接口被破坏 ⇒ 开关恒真**：`enabled()` 等 5 个函数一度返回 `(值, 是否回落)` 元组，
   调用点是 `if not enabled(...)` —— **非空元组恒真 ⇒ 环启用检查永不拦截**。
   "接线了却不设防"，比没接线更危险。现统一标量 + `--self-check` 6 项类型守卫。
2. **【P1】`retrieval_check` 直接 TypeError**：`limit = retrieval_budget(cfg, notes)` 拿到元组就比大小。
3. **【P1】`image_caption_requires_reading=false` 关不掉**：`if not required:` 分支是死代码。
4. **【P2】Loop A 状态文件路径漂移**：配置写 `<包>/.workbuddy/`，代码硬写 `<工作区>/.workbuddy/`。
5. **【P2】第 18 项"提示不阻断"导致 33 键反复被发现反复未处置**（v3.19.2 → v3.20.0 跨三版）。
6. **【P2】第 14 项版本位漏 2 处**：`language-profile.yaml` / `external-tools.yaml` 带 version 键却不在巡检清单。

## 五、诚实边界（本版不宣称的能力）

- `loop_a.trigger` / `loop_b.trigger`：**判环是语义判定**，代码不判——须主理人追问。
- `delta_gate.insert_font_at_creation`：**结构性不可判定**（写入时行为，成品文件态无痕迹）。
- `single_writer` **不防冒名**（平台无身份认证）。
- `check-path` **不是沙箱**（平台无 hook，拦不住成员绕开脚本直接写文件）。
- 判据层只做确定性判定（路径/集合/计数/格式/守恒），**不判条目的专业对错**。
- `patch_discipline` 判的是"有没有超出声明范围"，**不是**"改得多不多、该不该改"。
