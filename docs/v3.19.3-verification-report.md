## 一、L3 的核心发现：人读型白名单机制全面失效

这不是「75 个孤立死键」，而是一个**判据级缺陷**。三条证据链（均实跑）：

| # | 证据 | 实测 |
|---|---|---|
| ① | `known_textual` 登记的是**段名**（`"overlay_injection"`），而 walk 判据查**末段键名**（`leaf.lower() in known_textual`） | `overlay_injection.max_overlap_ratio` 的末段是 `max_overlap_ratio` ⇒ **永不匹配** |
| ② | `path_prefixes` 是**硬编码 7 个老段**元组（disease_modules/gates/ai_literacy/snapshot/fallback/members/domains） | 不含任何 v3.19.0 新增段 ⇒ `seg_hit` 兜底也失效 |
| ③ | 后果：v3.19.3 批次3 声称「已登记人读型」的 4 组键 | **实际全部仍在 dead 清单里**——体检第 18 项自己没守住自己的白名单 |

**⇒ 教训**：「登记/配置了」≠「生效了」。白名单类机制必须做**双向反例验证**
（登记在 → 消失 / 登记去 → 重现），否则是假绿。

## 二、75 键全量定性：33 键整批「声明了但没接线」

**结构性结论**：`loop_a`(4) + `loop_b`(20) + `delta_gate`(9) = **33 键 / 占 75 键的 44%**
整批声明未接线。

**根因**：v3.9.0「双层 Loop 契约下沉批」只把**动作层**下沉为代码
（loop 子命令 13 个动作），而 yaml 里的**默认值段 / 轮次复核判据 / delta 门禁判据**
三类仍是纯声明（代码字面量 0 处；`delta_gate` 在 `harness.py` 的 2 次出现是
**文件头 docstring**，非消费点）。

**处置（75 键逐条，理由据实）**：

| 类别 | 键数 | 处置 | 理由 |
|---|---|---|---|
| loop_a / loop_b / delta_gate | 33 | 登记人读型 | **声明未接线**（不谎称"由会话层消费"）；实际接线留 v3.20.0（残留·中） |
| stages.0..4.next | 5 | 登记人读型 + 新增第 24 项漂移守卫 | `next_stage` 代码 0 次，实际由 `current_stage` 数值驱动；yaml 与代码是双份真相 |
| caption_five_elements / caption_base_elements_note | 2 | 登记人读型（历史键） | v3.19.0 G4 明确标注「保留为历史键（向后兼容）」⇒ **不可删** |
| ima / standards / channels / terminology / english_allowed_when / consistency / english_minimum / visual-rules.gate / collapse / observability / report_only / license_uncertain_markers | 35 | 按段名/限定路径登记 | 契约说明、元数据、判据规则，消费方是会话层/成员；被脚本消费的键走 alive 分支优先，不受影响 |

**结果**：第 18 项 **75 → 0**（人读型登记 211 → 309）。

**附带修复**：第 18 项原只输出前 12 条，其余 63 条**永远不可见**
⇒ 人工无法复核 ⇒ 体检项形同虚设。已改为**默认全量输出**
（可用 `VET_DEAD_CONFIG_LIMIT=<n>` 截断，0 = 不截断）。

## 三、新增第 24 项：阶段顺序漂移守卫（阻断）

`stages.{i}.next == i+1`（末级为 None）。理由：yaml 的 `next` 与代码的
`current_stage+1` 是**同一事实的两处写法**，不一致即「配置说走 A、代码走 B」的静默分叉。

⚠ **守卫首版踩坑记录**（如实记录）：YAML 的 `0:` 键被解析成 **int**，
`stages.get("0")` 恒取到 None ⇒ 把「所有 next 都是 None」误报成 4 处漂移（**假红**）。
`harness.py` 里早有同款归一化注释（`{str(k): v for k, v in cfg["stages"].items()}`），
未参照 ⇒ 修正后归绿。
**教训：写守卫前先看同文件/同包已有的同类归一化。**
