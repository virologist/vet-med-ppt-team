## 四、本轮暴露并修掉的**同型缺陷**（值得单列）

本项目核心忌讳是「声明层 ≠ 执行层」。本轮又逮到 3 处**同型复发**：

1. **T11a 守卫首版是假的**：用 `if "institutional_endpoints" not in src` 判"是否接线"，
   反例验证时把读取改成 `inst_eps = []`（字面量仍在文件里）→ **守卫没红**。
   ⇒ 改 **AST 真实读取点**判据（`X.get("k")` / `X["k"]` / 字典字面量三种形态），反例随即报警。
   **教训：判据本身必须被反例验证过，否则它可能只是"看起来在守"。**
2. **`test_trace_events.py` 硬编码事件列表**（12 元组）——加了 `compaction` 事件后误报失败。
   ⇒ 改为从 yaml 读（唯一源）。**同型复发：同一口径两处各写一套。**
3. **`_intake_item_confirmed` 与 `_intake_item_state` 两份并行实现**（子代理与主理人各写一份，
   逻辑等价但口径不同）⇒ 合并为单一实现 + 薄封装。
   **教训：并行实现同型判据，是漂移的温床。**
