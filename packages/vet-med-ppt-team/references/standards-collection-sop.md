# 专业标准收录 SOP（v3.21.0 · 跨专业复用 · 用专业标准耦合 PPT 诊断与设计）

> **为什么有这份 SOP**：诊断维度 10 实测发现——`references/standards/` **只有 1 个文件**
<!-- DOMAIN_EXAMPLE_BEGIN -->
> （`animal-medicine-teaching-standard.md`），即本团的"专业标准耦合"目前**只服务动物医学**。
<!-- DOMAIN_EXAMPLE_END -->
> （哨兵块内是**现状举例**——第 23 项巡检豁免口径；本文件本身是**域无关 SOP**。）
> 而本团的目标是「可复用于任意教学/培训主题」——每接入一个专业，就该有一份该专业的
> **教学标准要求**，让 PPT 的页表、深度三档、能力落点有据可依，而不是凭经验拍。
>
> **本 SOP 的目标**：任何专业都能在 20 分钟内收录一份标准摘要，并接进
> ① 域档案的 `depth_scale_source`（深度三档出处）→ ② 闸 1 冻结清单（验收项）→ ③ 闸 4 终检（交付完整性门）。
>
> **唯一源分工**（不重复声明）：
> - 标准的**元数据与校验规则** = `config/external-tools.yaml#standards`（机器校验：哈希漂移 ⇒ 提醒）
> - 标准的**摘要正文** = `references/standards/<专业>.md`（人读；**不替代原文**）
> - 标准的**消费方式** = 本文件（流程） + `references/domain-profile-template.md#13`（怎么挂到域档案）

## 一、标准从哪来（唯一权威来源）

**教育部《XX专业教学标准》**——由教育部高等教育司组织、全国高等学校教学指导委员会制定发布。
它是"这个专业该教什么、教到什么程度"的**国家级依据**，与本团的用途完全对口：
- 规定**课程体系**（主干/核心课程）→ 对应 PPT 的模块与页序（`course_module_templates`）
- 规定**学时与实践占比** → 对应页数与实操页比例
- 规定**职业面向与岗位能力** → 对应案例形态与能力落点（`audience_profile`）
- 规定**能力要求层级**（了解/理解/掌握）→ 对应深度三档（`depth_scale_source`）

> ⚠ **本包深度三档的词汇口径**（`config/language-profile.yaml` 语境）：
> 三档是「了解 / 理解 / 掌握」，而**各专业教学标准用词可能不同**
> （有的用"了解/理解/掌握"，有的用"认知/理解/熟练"）。
> ⇒ 收录时**先核对该专业教学标准的原文用词**，再决定是否沿用本包三档；
> 若用词不同，在 `depth_scale_source.note` 里**写明对照关系**（不强行统一、不篡改原文）。

**不作为标准来源的**（避免把参考书当标准）：教材、教辅、行业白皮书、百科——它们是**教学来源**
（`evidence_hierarchy.teaching`），不是专业标准。

## 二、收录登记表（每份标准一份，复制模板填）

```markdown
# 教育部《XX专业教学标准》收录登记

| 项 | 值 |
|---|---|
| 标准全称 | 教育部《XX专业教学标准》 |
| 适用专业名称 | XX技术 |
| 专业代码 | <如 410301> |
| 发布机构 | 教育部高等教育司 / 全国高等学校教学指导委员会 |
| 发布年月 | <YYYY-MM> |
| 原文直链 | <URL>（**未核实就写"未核实"，禁止编造**） |
| 直链核验状态 | 已核实（YYYY-MM-DD）/ 未核实 |
| 本地摘要文件 | references/standards/xx-teaching-standard.md |
| 原文哈希 | sha256:<hex>（登记当时的原文指纹） |
| 摘要与原文的关系 | 本摘要**不替代原文**；需要精确条款时以现查 source_url 为准 |
```

**登记表就放在摘要文件的头部**（照 `references/standards/animal-medicine-teaching-standard.md`
的现有格式）——不要另建登记表文件（多一份真相 = 漂移源）。

## 三、摘要怎么写（**只写"对本团有什么用"**）

摘要**不复制原文条款**，只写 4 件事：

1. **课程体系** → 该专业主干/核心课程清单（名称 + 学时/实践学时 + 原文定位）
2. **职业面向** → 面向岗位与职业能力（原文表述 + 出处）
3. **能力层级** → 该标准用的能力动词及其与本包三档的对照
4. **对本团的约束**（这段是摘要的**真正目的**）：
   - 页表/模块模板该怎么组织（依据哪几条课程要求）
   - 深度三档该怎么落（依据原文用词）
   - 案例与实训页至少覆盖哪些能力点
   - 哪些内容**超纲不得进课件**（如有）

⚠ **引用精确条款时必须回原文定位**（章节号/页码），**不得**只写"依据教学标准"。
⚠ **摘要不得引入原文没有的判断**——推论要标"（推论：…）"。

## 四、变更怎么发现（机器机制，不是靠人记得）

`config/external-tools.yaml#standards` 已登记标准条目，含：
```yaml
verify:
  method: "sha256"
  note: "远端文件哈希与摘要登记值不符 ⇒ 标准已更新 ⇒ 提醒用户确认"
```
- 探针：`scripts/probe_channels.py`（对 `standards` 段做校验），结果记 `task_state.json`。
- 哈希不符 ⇒ **不自动改摘要**，而是**提醒用户确认**（标准可能已改版），
  由主理人决定是否更新摘要与登记值。
- ⚠ 现有 animal-medicine 条目里已有"本科版直链未核实"的先例——
  **如实标注未核实是正确做法**，不是缺陷。

## 五、怎么被消费（三个消费点，缺一则标准"收录了但没用"）

### ① 域档案的深度出处（`depth_scale_source`）
```yaml
depth_scale_source:
  standard: "教育部《XX专业教学标准》（本科版/专科版，YYYY-MM）"
  core_course: <该专业的核心课程名>
  note: <该标准的能力动词与本包三档的对照关系>
```
⇒ 装配器把该段注入成员 prompt（`【二、内容轴】`后的深度段），
成员据此判断"这页该讲到什么深度"。

### ② 闸 1 冻结清单（`config/harness.yaml#gate1_freeze`）
标准摘要是**验收项**之一（"本专业的教学标准要求已确认适用于本单"）——
`harness.py gate1-check` 会校验它是否就绪（未就绪 ⇒ exit 1 阻断进闸 2）。

### ③ 闸 4 终检的「交付完整性门」（`references/adjudication-rules.md`）
交付前核对：课件的模块组织/深度/能力落点**与本专业标准的对得上吗**？
这一条是**人判**（verifier 逐条对），不是机判——**不许假装有机器背书**。

## 六、跨专业收录流程（每接一个专业走一遍）

| 步 | 动作 | 产出 | 判据 |
|---|---|---|---|
| 1 | 找标准原文 | 教育部/教指委官网的该专业教学标准 | 直链**已核实**（或如实标未核实） |
| 2 | 建摘要 | `references/standards/<专业>.md`（含登记表头） | 4 项内容齐全 + 条款有原文定位 |
| 3 | 登记元数据 | `config/external-tools.yaml#standards` 加条目（含 `verify.method: sha256`） | 探针能校验到 |
| 4 | 挂到域档案 | 该域的 `depth_scale_source` 指向摘要 | 装配产物里能看到深度出处 |
| 5 | 收进闸 1 冻结 | `config/harness.yaml#gate1_freeze` 的对应项 | `gate1-check` 能查到 |
| 6 | 复验 | 跑一遍该域的 route→confirm→assemble | 深度段与标准一致 |

⚠ **第 1 步是硬约束**：直链未核实**不阻断收录**（如实标注即可），
但**不得编造 URL 或条款号**——本包铁律，宁可留白。

## 七、常见坑（都是本包实测踩过的）

| 坑 | 症状 | 修法 |
|---|---|---|
| 把教材当标准 | "依据教学标准"但引的是教材页码 | 教材进 `evidence_hierarchy.teaching`，不进 standards |
| 摘要替代原文 | 课件内容与标准原文对不上 | 摘要只写"对本团的约束"，精确条款回原文 |
| 编造直链 | 用户按直链点开是 404 | 未核实就写未核实（如实标注是正确做法） |
| 能力动词强行统一 | 把原文的"认知"改写成"了解" | 对照关系写进 note，不篡改原文 |
| 收录了但没挂上 | 标准文件在，但域档案/闸1 都没引用 | 走第六节 6 步，尤其第 4、5 步 |
| 哈希漂移不处理 | 标准改版了，摘要还是旧的 | 探针会提醒；主理人确认后更新摘要与登记值 |
