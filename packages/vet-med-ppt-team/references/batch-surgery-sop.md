# 批量版面外科 SOP（v2.0.0）

> 所有者：屠明熙（视觉规则引擎架构师）。消费方：A/B/C 轨批量脚本、郅作基（写回门禁）、主理人（裁决）。
> 制定依据：09-26 首战实测——元素重叠 486 处（14 份中占比 38%）居全部红灯之首，源头是 A 轨叠加层"只加框、不重排"；叠加注入的钩子文本试做 12pt、批量写成 8pt（R18 同型两张皮）。
> 阈值唯一数据源：`config/visual-rules.yaml`（本文件禁硬编码，引用 yaml 键名）。

## 1. 叠加层注入规范（A 轨轻改造专用，yaml#overlay_injection）

| 键 | 值 | 依据 |
|---|---|---|
| `min_font_pt` | 12.0 | 注入文本（预测钩子/任务卡/页脚/揭示语）一律按正文红线，禁 8pt/10pt"小字脚注"侥幸 |

> **v3.22.0 G1 补**：上表四键的**唯一源 = `config/visual-rules.yaml#overlay_injection`**
> （段名 `overlay_injection`，**不是** `batch_surgery`）。执行者 = `scripts/inject_notes.py`：
> 启动即读该段并打印一行，随后按「注入脚本前置断言」四条逐处判定。
> ⚠ 此段自 v3.22.0 起**有真实代码读取点**（此前只有声明、AST 读取点 0 处，
> 而本文声称「缺一即拒跑」——实际从未执行过）。
| `require_empty_slot` | true | 注入前必须探测空位：目标页无 ≥注入框尺寸的空白区 → **拆页**，禁止硬叠 |
| `max_overlap_ratio` | 0.15 | 注入框与任何既有文本框重叠超 15% = 注入失败，回滚该页 |
| `sample_review_ratio` | 0.20 | 屠明熙抽样复核下限 20%；verify_deck 报告的几何红灯页 100% 复查 |

**注入脚本前置断言（必须实现，缺一即拒跑）**：
1. 断言脚本已 Read visual-rules.yaml 并读取上述四键
2. 断言每处注入前执行空位检测（目标矩形与页内既有文本框两两求交，交面积/较小面积 ≤ max_overlap_ratio）
3. 断言注入字号 ≥ min_font_pt（写入前检查 sz 值）
4. 断言输出每页注入结果清单（页码/注入框坐标/字号/重叠检测值），供抽样复核

## 2. 降低信息密度（v3.5.0 新增，前置步骤）

> 经验来源：单页主框 250–430 字被要求压到 ≤150 字，实际耗了六轮返工（粗砍→转表格→调字号→拆任务→独立大表→微调）。
> 根因是**没有既定降密顺序**，每一轮随机选手段，且"先调字号"这条最危险的路被走了两轮（直接撞字号红线）。
> 原则：**降密先于几何修复**——内容压不下来的页，任何移动/缩放都是徒劳。

**固定执行顺序（yaml `density.shrink_order`，低级能解决不升级）**：

1. **删冗余**：与前文重复 >70% 的表述、无任务的装饰语、同义复述——删除清单报主理人确认（内容决策）
2. **转结构化**：把并列长句改表格/流程/图示（**压缩比最高且提升可读性，优先于一切几何手段**）
3. **拆页或移入备注**：超出 `density.max_body_chars_per_slide`（150，主框口径）→ 按语义单元拆页（规则见 §3-3），或把细节移入 speaker_note
   - ⚠️ **150 是真会被判 P1 的机器门禁，不是可忽略的建议**（v3.16.0 起已接线）：`verify_deck.py` 的「主框密度」检查超出发问题类型 `主框密度超标`，级别 **P1**（已显式登记 `visual-rules.yaml#severity.P1`），属"当次必清，可带计划写回"
   - **两层口径，不许糊成一个数**：**机器门禁 = 150 字**（唯一机器阈值，本文件 §2/§3 说的都是它）；**设计期自检目标 = 120 字**（给人提稿留 30 字余量、避免卡阈值边缘返工，**机器不读这个数字**）——见 `references/course-profile-defaults.md#硬约束1`；另有全页 400 字（发"文字墙" P1）。三者各司其职：400 看整页、150 看主框、120 看草稿
   - **降密到这里没到 150 以下的，不许靠改阈值过关**：调阈值属 B 类降级，按 **§8** 走三步
4. **调字号**：最后手段，且**不得低于 `font.body_min_pt`（12pt）**——低于此值禁止走本路径

**禁止**：❌ 为塞下更多字先降字号 ❌ 把超量文字压进图注/页脚小字区 ❌ 用"全页 400 字达标"掩盖"主框 300 字"（两个口径都要看）

## 3. 几何红灯修复顺序（重叠 / 文字墙 / 越界通用）

按代价从小到大，**逐级升级，低级能解决不升级**（先过 §2 降密再进本节）：

1. **缩小**：注入口缩小字号下限 = yaml `font.body_min_pt`（12pt），低于此值禁止走"缩小"路径
2. **移动**：在页内找空位平移（保持不越界，容差 yaml `geometry.offcanvas_tolerance_in`）；移动后重测与全部文本框的重叠。**正式工具：`scripts/surgery_deck.py`**（网格搜空位、注入卡优先迁移、避图 30%、找不到空位如实记 unresolved）
3. **拆页**：单页字符数超 `density.max_chars_per_slide`（400）且无法靠 1-2 处移动解决 → 拆页。拆页规则：
   - 按语义单元拆（一个机制链/一组鉴别要点/一张图+图注），禁止按行数机械对半
   - 拆出的新页必须带标题（原页标题+"（续）"）并继承备注
   - 拆页改变总页数 → **必须回报主理人重估课时口径**（页数是苏学法的预算）
4. **删冗余**：与前文重复 >70% 的段落、装饰性空框、无任务的"想一想"框——删除前列清单报主理人确认（删内容 = 内容决策，超出版面外科权限）

**禁止事项**：
- ❌ 禁止为消重叠把文字压到 <12pt
- ❌ 禁止把文字框移出画布"藏红灯"（越界检测会抓到，且属作弊）
- ❌ 禁止直接删图片/表格/机制图腾（医学生物安全红线：图像是诊断证据）

## 4. 修复验收

- 每页修复后：verify_deck 单页复验，该页 P0=0 且新增 P1=0
- 全部完成后：verify_deck 全量复验（`--level all`），对照 `deck_registry.json` 记录 P0/P1/P2/P3 前后值
- 残余 P1 必须逐处给出三选一结论：**已修 / 拆页 / 例外裁决（主理人签字）**——禁止"抽样未见问题"式空心结论
- ⚠️ **本节所有"修"都只指 §1-§3 与 §8.1 A 类手段**；凡涉及"降级"（调阈值 / 改 severity 映射 / 加豁免 / 关检查项）的，一律按 **§8 修复纪律：不得降级标准** 走三步，本节的三选一不授予降级许可

## 6. 与分级门禁的关系（v2.0.0）

- 元素重叠/文字墙 = **P1**：允许带修复计划中途写回磁盘，但交付前必须为 0
- 修复期间 P1 挂账须写入 `deck_registry.json`（郅作基维护），`age_days > 3` 冷启动自动报警
- 本 SOP 与 `sop-stages.md#闸4`、`adjudication-rules.md` 冲突时，以三者中更严格者为准

## 7. 幂等与断点续跑（v3.5.0 新增）

> 经验来源：一次 13 页批量施工在执行中段遭遇平台 5xx 集群错误中断，用户指令"请继续执行"，
> 因脚本非幂等，续跑存在重复建页/重复注入的风险，只能靠人工对账收尾。
> 原则：**批量脚本必须能被打断，也必须能被安全重跑**——中断不应导致重头再来，重跑不应产生第二份产出。

**四条硬性要求（郅作基驾驶批量脚本的前置断言，缺一即拒跑）**：

1. **单元化**：施工以"页/批"为最小单元，单元之间无共享可变状态
2. **进度落盘**：每完成一个单元即写进度记录（已完成单元 id 清单 + 落盘路径），中断后从**下一个未完成单元**恢复，不重头
3. **幂等键**：每个新建设元素带幂等键（如 `新建页锚点 + 预期标题`），重复执行时先查键，命中即跳过；**禁止无键的直接 append**
4. **重跑安全**：重复执行同一脚本 N 次，最终页数、文本、图片数与执行一次一致（可写自测：跑两次比对页数与形状计数）

**中断恢复流程**：① 读进度记录 → ② 对账已落盘单元（实际页数 vs 记录）→ ③ 从下一单元继续 → ④ 完工后全量复验（`--level all` + 增量基线比对，见 `adjudication-rules.md#增量门禁原则`）
**禁止**：❌ 中断后直接重跑全量（制造重复页）❌ 凭记忆判断"做到哪了"（必须读进度记录）

## 8. 修复纪律：不得降级标准（v3.16.0 新增）

> **立项依据（H5）**：本 SOP §1-§4 只规定了"怎么修"，**没规定"不许靠放宽标准来修"**；
> 而 `adjudication-rules.md#闸4 终检结构化清单` 给 verifier 的三选一（修 / 降级 / 例外签字）里带一个"降级"选项，
> 于是修复方可以靠调阈值、改 severity 映射、加豁免页把红灯"修没"。
> 本节的判据一句话：**消红灯 ≠ 消标准**——红灯消失必须是因为缺陷被消除，不是因为尺子变短。

### 8.1 可做的事优先于调参

消红灯的手段分两类，**默认顺序只能用 A 类**：

| 类别 | 手段 | 谁可决定 |
|---|---|---|
| **A 类（默认 · 先做尽）** | 拆页 / 删冗余 / 转结构化（表格 · 图示 · 流程）/ 下沉备注（speaker_note）/ 重新设计版式 | 执行方自行执行，事后报备主理人 |
| **B 类（降级 · 不得首选）** | 调阈值、改 severity 映射（如 P0→P1）、加豁免页或豁免项、临时关闭某个检查项、放宽判据 | **执行方无权自行决定**，一律走 §8.2 三步走 |

- **B 类不得作为首选手段**：动 B 类之前必须逐条写明 A 类五种手段**各自**为什么解决不了（写具体原因，不写"试过了不行"这类无信息量表述）
- **B 类不得由执行方自行决定**：无主理人签字的 B 类改动 = 未完成，门禁仍按原判据计（判据唯一源 `config/visual-rules.yaml`，本文件不硬编码阈值）
- **A 类内部顺序**沿用 §2 的 `density.shrink_order`（删冗余 → 转结构化 → 拆页/下沉备注 → 调字号），与本表不冲突：本表管"A 类 vs B 类"，§2 管"A 类内部先后"
- **"调字号"的归属（易混淆点，明确一下）**：改字号是**改产出**不是**改判据** → 属 A 类，但只能排在 A 类末尾（§2 顺序），且不得低于 `font.body_min_pt`；
  **把字号红线本身（12pt）往下调**才属 B 类降级，必须走 §8.2。同理，"把检出阈值从 0.15 放宽到 0.3"是 B 类，而"把重叠率从 39% 修到 0%"是 A 类

### 8.2 降级三步走（缺任一步 = 无效修复）

1. **主理人显式签字批准**：写明"降级 · 主理人批准"。落点 = `deck_registry.json` 对应条目的 `disposition` 字段；**对话里的口头同意不算**（对话不可审计、不可回滚）
2. **写明三件事**：① **理由**（A 类五种手段各自为何走不通）② **恢复期限**（哪一轮 / 哪个日期前必须恢复原判据，**不许写"后续优化"**）③ **受影响检查项清单**（逐项列：检查项名 + 原值 → 降级后值）
3. **留痕且可回滚**：随条目写入 `deck_registry.json`（`disposition` + 恢复期限），并落 trace —— `harness.py trace log --event degrade --actor <成员> --detail '<原因 · 恢复期限 · 受影响检查项>'`；回滚 = 把 yaml/映射改回原值并重跑门禁，**降级记录随条目保留不删**（回滚不等于抹掉历史）

### 8.3 反过来的情形：为让检查变绿而改判据 = 自引入缺陷

以下四类一律判为**无效修复**，并按**自引入缺陷**计（判据引用 `adjudication-rules.md#原则三 增量门禁`：验收基准是"自引入缺陷 = 0"，不是"绝对红灯 = 0"）：

| 行为 | 判定 |
|---|---|
| 为让体检/门禁变绿而放宽判据（阈值、覆盖率、字数口径） | 无效修复 + 自引入缺陷 |
| 为让测试通过而删断言、改预期、跳过用例 | 无效修复 + 自引入缺陷 |
| 为清红灯而加豁免页/豁免项 | 无效修复 + 自引入缺陷（除非已走完 §8.2 三步） |
| 只报"绝对红灯数下降"、不报基线比对 | 违反增量门禁报告格式（同上，按 `#原则三` 处理） |

> **只补空白、不重复立原则**：本节只补"降级"这一处缺口。
> 判据本身沿用 `adjudication-rules.md#原则三 增量门禁`（自引入缺陷 = 0 / 存量挂账不阻断 / 报告须带基线比对）
> 与 `adjudication-rules.md#反自评失真红线`（完成声明必须附机器计数与退出码）。
> **两处冲突时以更严格者为准**（与 §6 同规则）。

### 8.4 判定标记（谁执行 / 机器能查什么）

| 项 | 执行者 | 机器校验 |
|---|---|---|
| A/B 类归属判断、A 类五种手段是否已做尽 | 执行方自判 → **verifier 抽页复核（≥20%）** | ❌ **机器暂不校验** |
| B 类签字 + 理由 + 恢复期限 + 受影响清单 | **主理人**（唯一签字人） | ❌ **机器暂不校验**（`scripts/ensure_settings.py` 的 20 项检查中无对应项） |
| 留痕：`deck_registry.json` 的 `disposition` 字段 | 郅作基（台账维护） | ⚠️ **部分可查**：verifier 冷启动扫台账可判"有/无 `disposition`"，**不判三项内容是否写全** |
| 回滚（恢复期限到期是否真恢复） | 执行方执行，verifier 复核 | ❌ **机器暂不校验** |
| 阈值改动本身 | — | ⚠️ **部分可查**：`ensure_settings.py` 第 19 项只查 `_FALLBACK` 与 `visual-rules.yaml` 是否漂移，**不查"谁改的、有没有签字"** |

**诚实标注**：截至 v3.16.0，本包**没有任何脚本**校验"是否有人为消红灯而降级标准"——
本节 100% 靠主理人签字 + verifier 人工评审，**不装作有机器护栏**。
若将来要做机器校验，最小可行形态是"yaml 阈值 diff 且该 diff 未出现在任何降级记录中即报警"；**本版未实现，不做任何声称**。

**双向引用（防漂移）**：`adjudication-rules.md#闸4 终检结构化清单` 的「降级」选项指向本节；本节指向该文件的 `#原则三 增量门禁` 与 `#反自评失真红线`。**改任一侧的判据必须同时改另一侧。**
