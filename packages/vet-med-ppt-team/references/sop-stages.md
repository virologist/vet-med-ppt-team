## 闸 1｜任务冻结（主理人亲自主导，不调度成员）

1. 读对话与用户资料，区分「已知事实 / 用户偏好 / 待核实 / 建议性默认值」。知识库检索是严真奥的职责，主理人不直接搜 Ima。
2. 识别任务类型：新制作 / 旧课件优化 / 章节重构 / 汇报型。
3. **工具探针**（3 次调用内封顶）：主理人探通用能力（pptx→文本 / 图像生成 / 文件读取 MCP）；严真奥在闸 2 只探 Ima 专属工具（`ToolSearch` 查 `mcp__ima-mcp__*`），不重复通用探针。结果写 `task_state.json`。
4. **编排内核三步（机械动作，先于任何 spawn）**：
   ```bash
   H="python3 <专家包>/scripts/harness.py"; W="<工作空间>"
   python3 "$H" preflight --team <团队名> --workspace "$W"
   python3 "$H" route     --level L0|L1|L2|L3
   python3 "$H" state init --workflow WF-1 --stage 0 --workspace "$W"
   ```
   `preflight` 报 `degraded` 的成员按 `harness-engine.md#2` 降级处置（注入成员 MD 全文后由通用子代理执行），**不再整链阻断**。
5. 最多 5 个澄清问题（推荐答案+理由先给）。必问：教学主题与课程位置、授课对象及基础、时长、预期学习成果、课堂与制作条件。
   **旧课件优化另加三项强制裁决**（09-26 stage5 deviations 教训 + v3.5.0 页数口径事故）：
   ① **隐藏页处置**：恢复 / 删除 / 保留原状（默认保留 + 明示数量）
   ② **页数口径（三口径，v3.5.0 强化）**：报告与核对一律区分——
      - **物理页**：pptx 内全部 slide（含隐藏页）
      - **可见页**：正式课时计入的页（`--hours` 判定的分母）
      - **导出页**：PDF/图片等渲染产物的页（**隐藏页不出现，故与物理页必然错位**）
      跨载体核对页码必须先换算：`导出页码 ≈ 物理页序号 − 此前隐藏页数`；**凡报页数必标口径**，混用即判报告缺陷
   ③ **冻结 `--hours` 参数值**（v3.0.0：`--hours` 必填，**禁用按页数反推课时的自证式通过**）
5.1 **重复指令对账协议（v3.5.0 新增）**：用户重提已执行过的同类指令时（如再次下发同一组增补要求），
   **先对账再行动**，禁止直接重做、也禁止回一句"已完成"就收工：
   ① 逐条对照历史产出，标注 `已覆盖 / 部分覆盖 / 未覆盖`，附产出位置（页号或文件路径）
   ② 给三路径请用户选择：**A 验收现状**（出具验收证据收工）／**B 局部补强**（只做未覆盖与部分覆盖项）／**C 换方向深化**（在既有基础上做不同方向的增量）
   ③ 用户选 C 时，进入闸 2 的**方向裁决**（列方向 → 用户按强/中/弱分档 → 按档投入），不得默认"全方向重做"

## 闸 2｜设计（苏学法 ∥ 严真奥，并行）

输入：闸 1 确认结论。

1. **串行**（v3.17.0 批次 B 修正）：先 spawn **严真奥**（证据缺口清单）→ 拿到证据包后再
   spawn **苏学法**（蓝图）。
   **为什么不再是并行**：原写"并行、任务边界互斥"是错的——苏学法的**二八难点清单**
   明确依赖严真奥证据包里的「易误解」标注（见 `agents/pedagogy-architect.md`
   难点判定来源），两侧**存在真实数据依赖**，边界并不互斥。伪并行的代价是
   苏学法拿不到"易误解"标注而**必然回问**主理人，每次多一轮往返
   （`agents/vet-med-ppt-team-team-lead.md` 规定的"经主理人中转"路径被强制触发）。
2. 主理人汇编为【闸2｜教学蓝图】：受众与约束摘要 / 三层目标 / 流程与分钟级时间预算 / MECE 知识框架与页数区间 / 案例与形成性评价 / 证据缺口 / **二八难点清单** / 风险与待选项。
3. 页数区间由**苏学法在设计期锁定**（不得留给制作阶段试错；09-26 实战中"课时适配"反复返工 4 轮）。
3.1 **方案颗粒度四坐标（v3.5.0 新增，闸 2 交付物的验收项）**：任何增补/改造方案不得只交"内容清单"（加哪些页/哪些点）。
   每条增补必须挂上教学组织坐标，缺一即判颗粒度不合格、退回补全：
   | 坐标 | 要回答的问题 |
   |---|---|
   | 教学单元 | 落在第几课时/第几模块，前后如何衔接 |
   | 学习目标 | 服务哪个可观察目标（可评价动词），对应哪项评价证据 |
   | 岗位能力 | 对应什么岗位任务与能力点（职业本科/高职口径） |
   | 标准依据 | 依据什么行业标准、法规、规程（有文号的给文号，未核验的标【待核实】） |
3.2 **方向裁决（v3.5.0 新增，多方向深化必走）**：列出候选方向（产出形态 / 增量成本 / 教学增益 / 风险）
   → 请用户按 **强/中/弱** 分档 → 按档分配投入（强=重点、中=轻度、弱=仅挂账）。**未裁决不开工**（判据见 `adjudication-rules.md#迭代六原则`）。
3.3 **素材判读前置（v3.6.0 新增，方案涉图像/图表类内容必走）**：凡方案含"补图注 / 病例图教学化 / 图表增补"，
   设计阶段即须对涉及图像**逐张判读本体**（识图工具或人工），产出三栏判读记录：主体内容 / 可见特征 / 清晰度是否足以支撑教学判读。
   判读不出的特征不得进方案；低清图在方案中即降级标注"情境图"；判读记录随蓝图一并交确认——
   **禁止方案先行、施工时再看图**（那会让图注迁就预设而非事实，判据见 `adjudication-rules.md#迭代六原则#原则六`）。
4. 蓝图与固定页数冲突时：给可行区间与调整建议，不盲从。
5. **证据风险 = 低**时，可提议把证据核验并入闸 3 一次做完（用户同意方可）。
6. **请用户确认 → 确认门 2/2（设计确认）**。此后进入制作阶段不再逐段确认。

## 闸 3｜成稿（苏学法 ∥ 屠明熙，并行）+ 迭代回路

输入：已确认蓝图 + 证据包。

1. **并行 spawn**：苏学法逐页给教学列五字段（学习动作 / 学生可见内容 / 讲授提示 / `speaker_note`≥80字 / `page_role`）；屠明熙给版式列（版式类型 / 视觉焦点与层级 / 素材规格与许可 / 红线自检）。
2. **单边超时处理**：任一方超 `budgets.max_stage_minutes`（默认 20min）未回传 → 走 `harness.yaml#fallback` 降级（注入该成员 MD 全文由通用子代理执行），**不允许主理人因等成员无限阻塞**。
3. 合并为**单一页表**；形成性评价三件套齐备（低门槛识别 + 比较判读 + 整合决策）；页数落在锁定区间内（超出=拆页/合页，**不得缩字号硬塞**）。
3.1 **骨架冻结（v3.5.0）**：课时划分、模块序列、叙事轨为闸 2 冻结项，本闸只增补/替换/瘦身，
   不得顺手重组；确需改骨架 → 回退闸 2 重新确认（判据见 `adjudication-rules.md#迭代六原则`）。
3.2 **降密先行（v3.5.0）**：单页主框超 `visual-rules.yaml#density.max_body_chars_per_slide` 时，
   按 `shrink_order` 执行（删冗余 → 转结构化 → 拆页/移备注 → 调字号且 ≥12pt），
   **禁止先降字号**；详细判据见 `references/batch-surgery-sop.md#2`。
   ⚠️ **v3.16.0 起该键真的被机器判了**：超 150 字（标题/图注/页脚不计）由 `verify_deck.py` **直接判 P1**，
   问题类型 `主框密度超标`——此前 yaml 配了但无人消费，本闸不得再当作"只写不判"的软约束。
   另注意**两层口径别混**：机器线 = 150（P1）；`course-profile-defaults.md` 的 ≤120 是**设计期自检目标**，
   不是机器阈值。
3.3 **批量施工幂等与断点续跑（v3.5.0）**：脚本须单元化 + 进度落盘 + 幂等键 + 重跑安全，
   中断后按进度记录续跑并先对账，禁止重跑全量（详见 `references/batch-surgery-sop.md#7`）。
4. **迭代回路（原阶段 4，并入本闸）**：
   - 单页小改动：主理人按三清单自查，零 spawn
   - 跨模块改动：**非作者交叉复检**（科学性改动→严真奥视角；教学性改动→苏学法视角；页面性改动→屠明熙视角），只答「从我的专业视角会不会在我的领域埋雷」
   - v3.17.0：上条映射原先三处**全反**——把把关人派给了各自 agent MD 明文「你不做…（那是别人的事）」的人，等于把关被整体绕开。订正依据 = 各成员自述边界的取反（该领域归谁所有，就派谁复检）。**映射唯一源 = `config/guard.yaml#cross_review_mapping`**，由 `scripts/ensure_settings.py` 第 22 项（文档写法 == yaml 登记值）与 `scripts/test_arch_drift.py`#T8（yaml 登记值 vs agent MD 边界声明）双向强制；改本文必须同步改 yaml。
   - 改动影响上游已确认项时，明确提示需回退到哪一闸，经用户确认后重构
5. **不设确认门**（v3.0.0）：小改动直接推进，避免来回确认吃掉碎片时间。

## 闸 4｜交付（门禁 + verifier 独立复判 + 人工终审）

输入：定稿页表 + 课件文件。

1. **门禁（机器，唯一裁判）**：
   ```bash
   python3 <专家包>/scripts/harness.py gate --deck <课件> --hours <N> --level all
   ```
   - 退出码：`0` 通过 / `1` P0 硬阻断（禁止写回）/ `2` P1 阻断（可带修复计划写回，交付前清零）/ `3` P2 阻断（备注覆盖率不足）/ `4` **运行错误（非课件红灯，走缺陷回流修脚本）**
   - `--hours` **必填**，取闸 1 冻结的口径
   - **P2 覆盖率含机器草稿，但必须看 `machine_note_ratio`**：交付物需明示"其中 N 页为 AI 草稿，待教师复核"
1.1 **增量门禁（v3.5.0，改造类任务强制）**：施工前记录基线（P0/P1/P2 计数 + 页数三口径 + md5 + 关键串清单），
    施工后比对——**自引入 = 0 才准放行**，存量缺陷挂账不阻断；报告必写
    `P0=6（基线 6，自引入 0）` 格式，**禁只报绝对数**（详见 `adjudication-rules.md#迭代六原则`）。
1.2 **检出 ≠ 判定（v3.5.0）**：门禁与任何自动扫描报出的 MISS/命中，须经规范化复核后才定性；
    未经人工复核的 MISS 不得计入缺陷数、不得升级 P0（详见 `adjudication-rules.md#迭代六原则`）。
2. **verifier 独立复判（按需 spawn，闸 4 必调）**：自己重跑门禁 + 抽页 ≥20% + 对每条 P0 挂账给「修 / 降级 / 例外签字」三选一。**主理人与成员的"已达标"一律不作为依据。**
2.1 **三选一里的「降级」不是执行方可自选的常规选项**（v3.16.0 补：与 `adjudication-rules.md#闸4 终检结构化清单` 同型约束，
    防止走到本条路径就能绕过新规矩——两处授权强度必须一致）：凡选到「降级」（放宽判据 / 降 severity /
    加豁免页或豁免项 / 临时关检查项），必须走完 `adjudication-rules.md#「降级」选项的约束` 与
    `references/batch-surgery-sop.md#§8`（**判据唯一源**）的三步——
    ① **主理人显式签字**（写进 `deck_registry.json` 对应条目的 `disposition`；对话里的口头同意不算）→
    ② **写明理由 + 恢复期限 + 受影响检查项清单**（清单逐项列"检查项名 + 原值 → 降级后值"，恢复期限不许写"后续优化"）→
    ③ **留痕且可回滚**（`harness.py trace log --event degrade --actor <成员> --detail '<原因 · 恢复期限 · 受影响检查项>'`）。
    **缺任一步 = 未完成，门禁仍按原判据计；禁由执行方自行决定。**
    另：A 类手段（拆页 / 删冗余 / 转结构化 / 下沉备注 / 重新设计版式）须先做尽并逐条说明为何走不通才准提降级；
    为让红灯变绿而放宽判据 = **无效修复 + 自引入缺陷**。
3. **产物真实性双校验（约定→代码）**：
   ```bash
   python3 "$H" verify-artifact --path <成员产出绝对路径>
   python3 "$H" verify-envelope --path <成员产出绝对路径>
   ```
4. **写回纪律**：备份（`<原名>_备份_YYYYMMDD_HHMM.pptx` 同目录，禁 /tmp）→ 修改 → 门禁 → P0=0 才写回 → 台账记录（含 `judge_provenance`）。
5. **deviations 纪律**：`deviations_from_handoff` 非空时，属 P0/P1 的项**先组织修复**，不得作为待决事项上升给用户拍板；仅结构决策项（隐藏页/课时口径）可上升，且闸 1 已裁决过的直接执行、不再上升。
6. **外部操作**（上传/发布/共享）必须先向用户展示目标与范围并获明确授权。
7. **交付物必须含**：机器门禁原始输出片段、verifier 判决、机器草稿占比与待复核清单、挂账处置结论、未确认项标注。
8. **请用户终审 → 交付确认**。

## 闸 4.5｜案例三源核验（严真奥 ∥ 都衡言，并行）· 流程末端

> **v3.17.0 补写**：本闸自 v3.3.0 起即在状态机内（`config/harness.yaml#stages` 的 stage 4），
> 但本文此前**完全没有对应章节**——状态机能进、文档查不到，等于半条流程靠默契（文档漂移）。
> 本节与 yaml stage 4 逐项一致：成员 `dvm-content-expert` + `verifier`、gate `three_source_check`、
> `next: null`（**流程末端，无后继闸**）。

输入：闸 4 交付后的病例库台账（`<课程工作区>/.workbuddy/cases/cases_library.json`）。

1. **触发条件**：交付物含案例页，或病例库存在 `unverified=true` 的条目——二者满足其一即必走。
2. **盘点（只读，不改数据）**：
   ```bash
   python3 "$H" case-audit <课程工作区>
   python3 "<专家包>/scripts/case_extract.py" audit --workspace <课程工作区>
   ```
3. **并行 spawn**：严真奥补三源证据（`pubmed` / `textbook` / `regulation` 三类），都衡言独立抽检复算；
   两者边界互斥（**补证 vs 判罚**），主理人自评不作放行依据。
4. **核验协议**：详见 `references/case_extract_sop.md#5 三源核验协议`（三源类型、`sources` 字段 schema、失败处置）。
5. **阈值唯一源**：`config/domain_config.yaml#three_source_check`（`sample_rate` 抽检比例 / `pass_threshold` 通过率）。
   **禁止在本文或任何脚本里另写一份**（第 21 项体检守这条：重复声明会静默失效）。
6. **失败不阻断入库**（Q4）：核验不过留 `unverified=true` + `sources[].ok=false` + `reason`；
   **禁把未核验内容当已核验写进课件**。
7. **治理触发**：`unverified_count` 长期不下降 → 触发治理整顿（见 `case_extract_sop.md#7`）。
8. **流程末端**：`next: null` 表示本闸之后**没有后继闸**——任务在此收口；
   交付、复盘与下一轮输入由主理人在闸 4 终审与本闸产出合并处置（不得为"再确认一次"另开闸）。
