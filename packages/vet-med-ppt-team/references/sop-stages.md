# 六阶段门控流水线完整 SOP（主理人按需加载）

> 本文件是主理人 MD 中「六阶段索引表」的展开细节。主理人在进入对应阶段时 Read 本文件的对应章节，不全文预载（上下文纪律）。

## 阶段0：任务冻结与澄清（主理人亲自主导，不调度成员）

1. 读取对话上下文与用户提供的资料；区分「已知事实/用户偏好/待核实/建议性默认值」。知识库检索是严真奥的职责，主理人不直接搜Ima。
2. 识别任务类型：新制作 / 旧课件优化 / 章节重构 / 汇报型（课程汇报、实训汇报、学术汇报、教学竞赛）。
3. **工具探针（旧课件优化/汇报型必做，新制作可选；探测职责分工防重复）**：主理人统一探测**通用能力**（pptx→文本转换 / 图像生成 / 演示文件生成 / 文件读取MCP），一次性记入任务状态；严真奥在阶段2开头只探测**Ima专属工具可用性**（ToolSearch查`mcp__ima-mcp__*`），不再重复通用探针。探测总花费控制在3次调用内（旧课件1次+严真奥Ima 1次+备选演示生成1次），禁止无限枚举。
4. 按重要性排序提出最多5个澄清问题（推荐答案+理由先给，再问）。必问项缺一不可：教学主题与课程位置、授课对象及基础、时长、预期学习成果、课堂与制作条件。
5. 涉及传染病、病原操作、公共卫生敏感内容时，额外确认：仅讲授原理与诊断思路，还是包含经机构批准的教学实验；不擅自提供超出课程安全边界的操作细节。
6. **输出**【阶段0｜任务澄清】已知信息 / 待确认问题 / 默认建议及影响（含工具探测结果）。用户未答复前不输出任何方案。

## 阶段1：教学蓝图（并行：苏学法主笔 + 严真奥供证据缺口清单）

输入：阶段0确认结论。
1. TeamCreate 后，按「下发任务包 schema」分别 spawn 苏学法（蓝图任务包）与严真奥（证据缺口任务包），二者并行。
2. 主理人汇编为【阶段1｜教学蓝图】：受众与约束摘要 / 专家路由说明 / 三层目标 / 流程与时间预算 / 知识框架与页数 / 案例与评价设计 / 需联网核验问题 / 风险与待选项。
3. 等待用户确认。**若用户要求固定页数与时长/受众冲突，给出可行区间与调整建议，不盲从。**蓝图确认时若证据风险=低（缺口清单全部标注「可安全沿用教材表述」），向用户提议跳过独立阶段2、把证据标注并入阶段3页面脚本；用户同意方可跳过。

## 阶段2：证据核验（串行：严真奥主力，主理人监督）

输入：已确认蓝图 + 证据缺口清单。
1. 严真奥按任务包执行 ReAct 核证循环（详见其 MD）；主理人只监督进度与红线，不干预检索策略。
2. 流行病学数字、疫情分布、诊疗防控建议必须标明适用地区与年份。
3. **输出**【阶段2｜证据包】。等待用户确认。

## 阶段3：页面级教学设计（并行：苏学法 + 屠明熙，主理人汇编）

输入：确认后的蓝图与证据包。
1. **并行调度**（同TeamCreate后同一消息里spawn 苏学法与屠明熙）：苏学法逐页定义教学列；屠明熙逐页给出版式列。**单边超时处理**：任一方spawn超时>5min未回传，主理人按"该页教学列/版式列"降级——教学列降级为"学习动作=识别/理解（默认动词），具体内容留待阶段4补全"；版式列降级为"版式类型=左文右图（默认安全版式），素材规格待定"。不允许主理人因等成员阻塞整个流水线>10min。
2. 叙事链强制：问题/情境 → 证据/机制 → 判断/行动，禁止按教科书目录平铺。
3. 形成性评价三件套必须有：低门槛识别任务、比较判读任务、整合决策任务（附教师参考答案与常见误区）。
4. **输出**【阶段3｜页面级脚本】：单一合并页表（每页一行或一卡，七字段）。等待用户确认、删改、重排。

## 阶段4：迭代修订（快速通道 + 交叉复检）

输入：用户对阶段3的修改意见。
1. 判定修改影响范围：单页 / 模块 / 时间预算 / 学习目标 / 证据包 / 全局视觉。影响上游已确认项时，明确提示需回退的阶段与原因，经用户确认后重构。
2. 质检分轨（v1.7.0 交叉评估版）：
   - **单页级小改动**：主理人按三项清单自查，零 spawn。
   - **跨模块改动**：**交叉复检**——复检人必须是「非产出该内容的成员」：
     - 科学性改动 → 复检人：苏学法（相邻视角：教学内容是否承接得住该科学改动）
     - 教学性改动 → 复检人：严真奥（相邻视角：教学改动是否引入科学表述风险）
     - 页面性改动 → 复检人：苏学法（相邻视角：版式改动是否破坏教学叙事）
     - 交叉复检人只回答一个问题：「从我的专业视角，这个改动会不会在我的领域埋雷？」不重做全量审查。
   - 只传变更页diff与相关证据片段，不传全量脚本。
   - 主理人已对其中某项自查通过时，回传注明「该项已自查，无需重检」。
3. 小改动修订后直接进入阶段5；跨模块改动保持确认。

## 阶段5：制作交付（v1.9.0：郅作基=执行工程师守门禁；L0-L1 主理人可亲自施工）

输入：确认后的最终页面脚本。
1. **路径决断权属主理人**：按路径B优先规则（存在待处理 .pptx 时 B 默认）下发 next_action。郅作基按主理人下发的字段执行，不自主选择。
2. 路径B执行约定：郅作基移交"需求卡+合并页表+全局视觉规范+证据包关键标注"给 teaching-ppt-studio；收到 handoff_out.json 后**必查 `deviations_from_handoff`**，非空时不得自行决定——立即转主理人裁决；仅当为空数组时方可自主整合并交付。
3. 路径A输出六件套：A 总提示词 / B 全局视觉规范 / C 逐页生成指令 / D 图像素材清单 / E 可编辑性要求 / F 导出与投影检查清单。
4. **写回门禁（v1.9.0 硬性，无例外）**：无论谁施工（脚本/主理人/成员），课件写回磁盘前必须 verify_deck 红灯清零 + 快照 manifest 页数核对 + 备份确认（郅作基职责，主理人亲自施工也不例外——R18 事故 258 处字号红灯教训）。
5. **主理人终检（结构化清单，见 adjudication-rules.md 终检节）**：逐项打勾，任一项不过即打回。
5. 实际创建、上传、导出、共享等外部操作，必须先向用户展示完整目标与范围并获明确授权。

## 任务状态文件规范（长任务防上下文丢失）

任务启动时主理人创建 `<workspace>/.workbuddy/task_state.json`：

```json
{
  "task_id": "<timestamp+random>",
  "workflow": "WF-1|WF-2|WF-3",
  "current_stage": 0,
  "stage_history": [{"stage": 0, "status": "confirmed", "ts": "...", "summary": "..."}],
  "user_confirmations_pending": [],
  "tool_probe_results": {"ima_mcp": true, "markitdown": false, "pptx_venv": true, "image_gen": true},
  "next_action": "stage_1_spawn",
  "compaction": {"must_keep": ["task_id", "current_stage", "关键决策摘要", "next_action"], "dropped": ["已确认阶段的中间细节"]}
}
```

- 每阶段完成后更新 stage_history 与 current_stage；用户每次确认后清空 user_confirmations_pending。
- 长任务中断/切换会话时，主理人在阶段0末尾必 Read 一次此文件恢复状态（优先级高于 MEMORY.md）。
- **并发会话冲突防护**：写入前原子比对 task_id，不一致立即停止推进并向用户报警，绝不允许两会话互相覆盖。

## Compaction 最小集策略（v1.7.0 新增）

上下文接近上限或会话切换时，task_state.json 的 `compaction.must_keep` 字段必保以下四项，其余可丢弃：
1. `task_id` 与 `workflow`
2. `current_stage` 与 `next_action`
3. 本阶段关键决策摘要（≤3行：用户确认了什么、否决了什么）
4. 涉及的文件绝对路径清单

冷启动恢复 = Read task_state.json 最小集 + Read 本文件对应阶段章节，**禁止重读全部历史上下文**。
