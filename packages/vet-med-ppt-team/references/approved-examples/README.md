# 认可样例库（approved-examples）

> v3.31.0 新建。**这是什么**：用户明确认可的真实产出（课件、页表、诊断报告、说明文档），
> 连同「为什么被认可」的判据，收敛成一份**可被查、可用、可比对**的样例集。
>
> **为什么需要（2026-11-11 真实运行取证）**：
> 本包的反馈闭环此前只有三条通道（用户裁决 / 缺陷回流台账 / 学习条目），
> **没有「好样例」这一面**——`.learnings/LEARNINGS.md` 里 LRN-023 自陈
> 「登记 ≠ 行为约束，同型错误第三次复发」，而「登记」本身也只是**又一条散文**。
> ⇒ 教训要真正防复发，需要**可被检出的反面判据**或**可被模仿的正面样例**。
> 本库提供后者：**合格产出长什么样，有可核对的样本**。
>
> **本文件只登记事实与判据**（做什么 / 从哪来 / 校验和 / 适用边界）；
> 代码只管定位与校验（`scripts/check_contracts.py` 的 C7）。
> **两者分开**：文档里不堆脚本逻辑，脚本里不写选样理由。
>
> ⚠ **与 `scripts/sample_fixtures.py` 的分工**：后者是 v3.24.0 起就存在的
> **外部课件样本定位层**（供测试找样本用，解决「样本在哪」），
> 与本库（解决「合格产出长什么样」）是**两件事**，不共用登记册。

---

## 1. 收录标准（**不满足即不收**）

一条样例要被收录，必须同时满足：

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | **被用户明确认可**（不是「自评通过」，是用户裁决为接受/部分接受） | 轮报记录或用户原话 |
| 2 | **有唯一标识与校验和**（sha256） | 机器可核 |
| 3 | **有可复现的合格判据**（哪些机器项过了、哪些人工项过了） | 判据表 |
| 4 | **标注适用边界**（什么主题/什么受众下成立） | 边界声明 |
| 5 | **不包含受限内容**（无未授权个人信息、无生物安全越界操作细节） | 人工复核 |

> ⚠ **不收「看起来不错」的样本**：未经用户认可的产出收进来，
> 会把「AI 自认为好」固化成「标准」——这正是本包最忌的自评失真。

## 3. 与其他机制的关系

| 机制 | 管什么 | 本库的关系 |
|---|---|---|
| `references/defect-reflow.yaml` | **反面**：规则改动 → 产出侧有无变化 | 互补（缺陷回流管「改规则是否生效」，样例库管「产出长什么样」） |
| `.learnings/LEARNINGS.md` | **教训**：跨会话经验 | 互补（教训是「不要做什么」，样例是「要做什么」） |
| `scripts/verify_deck.py` | **机器判据**：单份课件的确定性检查 | 样例库的 `machine_passed` 记录**当时**过了哪些项 |
| `references/seven-dimension-rubric.md` | **人工判据**：七维量规 | 样例库的 `human_passed` 记录**当时**人工过了哪些维 |

> ⚠ **样例不替代判据**：样例是「参考」，判据是「规矩」。
> 判据可机器执行的部分**永远以判据为准**；样例只用于「判据没覆盖的主观面」。

## 4. 使用方式

### 4.1 查询（AI 冷启动可发现）

```bash
python3 scripts/check_contracts.py            # C7 项会报告样例库状态
```

### 4.2 收录（人工动作，脚本不代劳）

1. 用户裁决「接受 / 部分接受」→ 拿到**被认可的产出文件**；
2. `shasum -a 256 <文件>` 固定校验和；
3. 按 §2.1 格式在本文件 §2.2 追加一行；
4. 跑 `python3 scripts/check_contracts.py` 确认 C7 绿。

> ⚠ **脚本不自动收录**：自动收录 = 未经用户认可就进标准库 = 自评失真。

---

## 5. 维护纪律

- **改动样例文件本身** ⇒ 必须同步更新 sha256，否则 C7 判红（样例漂移）；
- **样例库满 20 条** ⇒ 触发一次**回顾**：哪些判据反复被认可？⇒ 考虑晋升为机器判据；
- **样例长期未被引用** ⇒ 标记为 `stale`，不必删除（历史判据仍有价值）。
