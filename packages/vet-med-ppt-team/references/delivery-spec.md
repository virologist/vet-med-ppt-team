# 交付三件套规范（Loop B 终交付）

> 建立：v3.10.0 · 上位：`course-profile-defaults.md#5`（用户 2026-10-22 指定交付形式）
> 适用：Loop B 制作阶段通过 `make-gate` 后的最终交付。**三件缺一不得宣告完成。**

## 1. 三件套清单

| # | 交付物 | 形态 | 硬要求 |
|---|---|---|---|
| 1 | **修改后的 PPT 文件** | `.pptx` | 原件不动（新文件另存）；模板继承；打开/渲染无异常 |
| 2 | **逐页修改说明** | `.md` + 可导出 `.csv` | **逐页**成条，不得"整体优化"概括；每条含改动前后对照与依据 |
| 3 | **验收自检清单** | `.md` | 逐项打勾且**每项给判定依据**；未检查项写原因，不得写"看起来没问题" |

命名约定（与既有工作区一致）：

```
<课程名>_v<版次>_<受众>_<课时>.pptx
<课程名>_v<版次>_逐页修改说明.md
<课程名>_v<版次>_验收自检清单.md
```

## 2. 逐页修改说明 schema

**逐页一条**，页序与成品一致；无改动的页也要出现（写"本页无修改"并说明为何保留——
静默跳过会让人以为漏看了）。

| 字段 | 必填 | 说明 |
|---|---|---|
| `page_id` | ✅ | 稳定页 ID（`round-review-sop#3`），不用页码（页码会变） |
| `页码（新/原）` | ✅ | 便于人工对照 |
| `诊断条目` | ✅ | 引用诊断条目 ID（八字段条目）；无条目则写"—" |
| `维度` | ✅ | 六查之一：标题层级 / 正文表述 / 图表 / 案例 / 思考题 / 小结 |
| `修改前` | ✅ | 原文摘录（≤80 字，长则摘关键句） |
| `修改后` | ✅ | 新文全文或关键句 |
| `修改依据` | ✅ | 来源定位（文献/指南/教材 + 年份）；无来源须标 `[待核实]` |
| `配图决策` | ✅ | 保留 / 替换 / 新增 + 页面内位置；无图页写"—" |
| `轮次与批准` | ✅ | `round=N` + 用户裁决（接受/部分接受/返修后接受） |
| `未决项` | ➖ | 挂账的问题与后续建议 |

CSV 列顺序即上表顺序（便于 Excel 排序筛选与存档）。

**最小示例**：

```markdown
| page_id | 页码(新/原) | 诊断条目 | 维度 | 修改前 | 修改后 | 修改依据 | 配图决策 | 轮次与批准 | 未决项 |
|---|---|---|---|---|---|---|---|---|---|
| p014 | 14/13 | D-007 | 正文表述 | "本病死亡率可达100%" | "急性型死亡率可达 80%–100%（视具体致病型与日龄）" | 《XX学》第14版 2020，p.231 | 保留 p014 临床图（右下） | round=2 接受 | — |
```

## 3. 验收自检清单 schema

三段式：**① 通用内容 5 条 → ② 通用视觉 7 条 → ③ 受众/课时差异化项**。
每项必须给出 `判定标记`（[机]/[人]/lint 未实现）与 `判定依据`（命令名 + 输出摘要 / 人工核验方式）。

```markdown
# 验收自检清单 — <课程名> v<版次>

<!-- DOMAIN_EXAMPLE_BEGIN -->
- 受众：①职业本科  课时：2（90min）  模板：5fa78154（禽病防治技术PPT模板）
<!-- DOMAIN_EXAMPLE_END -->
- 成品：<文件名>.pptx  sha256：<前12位>
- 原件：未改动（sha256 与开工时一致：<前12位>）

## A. 内容（C1–C5，course-profile-defaults#4.1）
| # | 项 | 结论 | 判定标记 | 判定依据 |
|---|---|---|---|---|
| C1 | 知识点准确 | 通过 | [机]+[人] | verify-ref 12/12 命中；2 条 [待核实] 已移出正文 |
...

## B. 视觉（V1–V7，course-profile-defaults#4.2）
| V7 | 无文字溢出或遮挡 | 通过 | [机] | ooxml_lint --geo-baseline：新增重叠 0，inherited 41 条（模板固有） |
...

## C. 受众/课时差异化
| 项 | 阈值 | 实测 | 结论 |
|---|---|---|---|
| 正文字号下限 | 18pt | 最小 18pt | 通过 |
| 单页主框正文字数 | **机器门禁线 ≤150**（唯一源 `visual-rules.yaml#density.max_body_chars_per_slide`；超了 `verify_deck.py` 判 **P1 · 主框密度超标**）／**设计期自检目标 ≤120**（人读，非机器阈值） | 最大 112 | 通过（机器线与人读目标**均**达标） |
| 互动页占比 | ≥10% | 4/28=14% | 通过 |
| 课时末小结页 | 2 张（每课时 1） | 2 | 通过 |

## D. 未检查 / 未实现项（不得留空）
| 项 | 原因 |
|---|---|
| 音频/视频对象可编辑性 | lint 未实现，人工未覆盖 |
```

## 4. 与既有验收的关系（不重复造轮子）

本清单是**交付物的规范**；判定标准仍以两处为准，不在本文件重定义：

- 内容与证据：`round-review-sop.md#11` 终审验收清单 10 项
- 视觉与受众阈值：`course-profile-defaults.md#4`

冲突时：`course-profile-defaults.md#4`（用户已确认的验收标准）**优先**。

## 5. 交付前硬检查（`harness.py loop make-gate` 已内建）

1. A 类 intake 五项 `status` 全 `confirmed`
2. 全部诊断条目已冻结（`frozen_items` 覆盖 `items`）
3. `verify` 无 sha256 漂移（`invalidated` 为 0）
4. 原件 sha256 未变
5. `ensure_settings` 15/15 + 全部 `test_*.py` 通过（新建能力未回归）

任一不过 → 不得交付，退回对应阶段；**不得因期限临近跳过**（期限不构成放行理由）。
